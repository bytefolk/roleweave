# 执行岗位参考库

十四个专业岗位组成产品、研发、市场、交付运营四类团队。职能与协作方法由案例配置，头衔不授予权限。

| 稳定 ID | 团队 | 岗位 | 交付职责 |
| --- | --- | --- | --- |
| product-manager | 产品团队 | 产品经理 | 将目标转成明确范围、优先级和可检查的产品规格。 |
| user-researcher | 产品团队 | 用户研究员 | 整理用户问题、证据缺口和可执行的研究计划。 |
| interaction-designer | 产品团队 | 交互设计师 | 把产品范围转为可审阅的用户流程和交互规格。 |
| engineering-lead | 研发团队 | 研发负责人 | 协调技术任务、接口约定、实现整合与验证。 |
| software-architect | 研发团队 | 软件架构师 | 确定实现边界、数据结构、接口契约和技术取舍。 |
| frontend-developer | 研发团队 | 前端开发工程师 | 按交互与接口约定产出前端实现草稿，说明限制和验证方法。 |
| backend-developer | 研发团队 | 后端开发工程师 | 按数据与接口契约产出后端实现草稿及验证说明。 |
| test-engineer | 研发团队 | 测试工程师 | 独立检查交付是否符合验收项，提供可定位的问题和证据。 |
| campaign-strategist | 市场团队 | 营销策划负责人 | 定义受众、市场定位、渠道选择及活动验收方式。 |
| content-creator | 市场团队 | 内容策划 | 基于批准的产品信息产出可审阅的营销内容。 |
| growth-analyst | 市场团队 | 增长分析师 | 设计增长实验和指标，分析证据而不虚构效果。 |
| delivery-lead | 交付运营团队 | 交付负责人 | 整合团队交付、协调依赖并组织用户验收。 |
| project-coordinator | 交付运营团队 | 项目协调员 | 维护任务、依赖、状态和交接记录。 |
| customer-support-analyst | 交付运营团队 | 客户支持分析员 | 整理支持问题、反馈假设和交付说明。 |

定义见 [catalog.json](catalog.json)，方法来源见 [methods.json](../methods.json)，团队和负责人见 [teams.json](../teams.json)。
