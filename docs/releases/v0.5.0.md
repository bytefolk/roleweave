# RoleWeave 0.5.0

RoleWeave 0.5.0 adds local Agent connections, desktop resource uploads, delivery-acceptance context and company examples. It includes the 18 commits after v0.4.0 through main revision `051ef22dc8931cf60fbf0eac7b9ebae74f5c248f`; the preparation commit updates release documentation. The [public release record #604](https://github.com/bytefolk/roleweave/issues/604) tracks the reviewed commit, checks, publication and asset verification. The earlier [local Windows upgrade #592](https://github.com/bytefolk/roleweave/issues/592) did not publish installers or advance update feeds.

## Changes

- Local connections: Windows WorkBuddy desktop login can serve WSL employees through the desktop private channel. Qwen Office gains a distinct native client connection with dedicated employee sessions, task progress, results and owned-task cancellation.
- Agent readiness: Codex checks the CLI actually selected for execution and the required launch options. Qoder probes avoid starting the editor launcher. WorkBuddy model selection uses its own connection information.
- Employee settings: compact identity, skills, connectors and advanced permission sections, input validation, and detection of unchanged grants. Qwen Office employees keep their client-owned settings in Qwen Office and support name editing in RoleWeave.
- Organization and projects: accessible search, clear, expand and collapse controls; consistent project list, board and schedule spacing; theme-aware layouts and bounded scrolling.
- Conversations: rich replies in individual, group and streaming views; clickable URLs with Chinese punctuation handling; workspace-resource navigation; preserved line breaks, emphasized labels and code-copy feedback. Format guidance preserves explicit user formats and the original stored request.
- Inbox and graphs: shared workbench surfaces, bounded approval details, and clearer graph exploration paths and resource previews.

- Resources: a clearer shared-resource workspace and image previews; upload files directly to Mem with a 32 MiB per-file limit, duplicate handling and list refresh. Windows transfers bytes to the WSL control plane without sending desktop paths. Invalid or insufficient drive credentials show actionable service guidance.
- Delivery acceptance: buyer-side delivery details and acceptance context are read from the existing approval contract.
- Execution and reliability: a compact progress/status row and native tray showing active tasks, pending approvals and disconnection; scoped Claude Read/Glob/Grep execution with iteration budgets and no phantom tool completion; clearer Codex connection recovery; updated Qoder and Qwen Office icons; correct UTF-8 streaming, original-question knowledge retrieval and Gemini process cancellation.
- Examples: a 25-role CXO reference catalog, three company scenarios, execution teams and collaboration runbooks. Synthetic tasks produce read-only plans and drafts; they do not deploy a product.

## Compatibility and upgrade

This remains a pre-1.0 preview. Existing employee bindings and workspaces retain their identities. Install over the existing per-user Windows application; workspace files, conversation history and user settings are retained.

Qwen Office uses its own native tools, approvals, current model and usage accounting. RoleWeave employee tool grants, position modes and per-task token budgets do not restrict that client's tools. Review permissions and pending approvals in Qwen Office. Missing usage stays unknown, and connecting a client does not establish entitlement for every model or task.

## Downloads and validation

- macOS Apple Silicon: `roleweave-0.5.0-arm64.dmg` and `roleweave-0.5.0-arm64.zip`.
- Windows x64: `roleweave-0.5.0-x64.exe`.
- Intel Mac, Linux and native mobile installers are not included.

The distribution uses the existing unsigned desktop channel: macOS packages are not Apple Developer ID-signed or notarized, and Windows packages are not Authenticode-signed. The macOS app verifies the separate signed update manifest, downloads updates in the background and replaces the app on normal exit. Windows verifies the installer checksum against the HTTPS feed and requires confirmation. Publication advances the public update feeds.

Windows v0.3.0 clients that disable in-app installation need one manual upgrade. Existing v0.4.0 clients can use their normal update flow. External Agent installations, client accounts and service entitlements remain operator-managed.

CI checks Linux/macOS source gates, both native staging startup/layout lanes and both installer formats. User-machine installation, uninstallation, real provider entitlement and cross-version updates require separate product validation; CI does not establish those results.
