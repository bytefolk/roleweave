# 智能协作建议（预览）

跟踪：[#447](https://github.com/bytefolk/roleweave/issues/447)。产品方案见 [#446](https://github.com/bytefolk/roleweave/pull/446)，研究背景见 [#422](https://github.com/bytefolk/roleweave/issues/422)。本切片从 main 独立实现，不包含 #423 / #429 的开发分支功能。

## 使用场景

负责人在上报中心看到几个失败执行，希望知道下一步该检查预算、Agent 连接还是执行记录。启用后，可以为已有失败记录主动生成一组参考建议；执行记录、顺序、汇报链和追溯入口始终保留。建议不代表优先级或风险结论，也不会自动重试、分配任务或批准操作。

## 开启与使用

1. 打开项目，进入 **设置 → 实验功能 → 智能协作建议 · 预览**。每个项目默认关闭。
2. 阅读服务提供方和发送范围，点击 **同意并开启**。设置立即保存到当前项目，不需要点击应用配置的保存按钮；此时不会调用外部服务。
3. 进入 **上报中心 → 失败升级**，点击 **生成建议**。每次只检查最近最多 20 条失败或待确认记录，界面显示实际检查数量。
4. 按建议查看原始记录，再自行决定下一步。信息不足时显示“信息不足”，不会补造原因。

再次点击生成时，相同快照可能使用本项目最近 5 分钟的缓存；服务失败缓存 30 秒，避免连续点击造成重复外呼。页面加载、报告刷新、SSE 执行通知和开启开关本身均不调用 Jev。切换项目或关闭开关会取消本地待处理请求并丢弃迟到结果；已经发送的网络请求不能撤回，已有执行和上报历史不会删除。

## 服务与数据范围

固定服务为 **Jev / TypeSafe**，目的地址为 `https://api.typesafe.ai/v1/systemone`，不接受可配置代理或重定向。请求按 [TypeSafe 官方 API 契约](https://docs.typesafe.ai/api) 构造 Choice 问题，输出仅能选择本地定义的调查步骤。

仅向服务发送执行状态、规范化错误码、是否与预算相关三个元数据字段，以及固定问题模板和模型标识。未知错误码统一归入 `other`。本地关联 ID、员工姓名、汇报链、项目路径、消息、任务、文档及附件内容不进入请求。

开启不是上传正文的授权。此预览也不证明元数据判断优于现有规则；真实服务准确率、建议采纳率、延迟和费用仍需在获得服务访问后单独评估。低置信度会显示为信息不足，当前保护阈值不是经过业务样本校准的准确率承诺。

## 本机维护者配置

凭据只由控制面进程读取，不能写入项目实验设置或从渲染器提交。在启动 RoleWeave 的进程环境中配置：

| 环境变量 | 用途 |
| --- | --- |
| `ROLEWEAVE_JEV_API_KEY` | TypeSafe 服务凭据；缺失时不外呼，界面显示服务未配置 |
| `ROLEWEAVE_JEV_MODEL` | 可选，默认 `jev-latest` |
| `ROLEWEAVE_JEV_TIMEOUT_MS` | 可选，默认 2000 ms，运行时限制在 100–5000 ms |

变更环境后重启控制面，再刷新状态。请使用本机已有的秘密管理方式提供凭据，不要把密钥提交到仓库、项目配置、截图或评审消息。历史研究分支的 `ROLEWEAVE_JEV_ENABLED` 和 `ROLEWEAVE_JEV_URL` 不控制此实现；允许使用由当前项目开关决定。

Windows 的 WSL 控制面模式支持通过既有 stdin 配置桥传入这三个环境变量；密钥不会进入命令行参数。也可由 WSL 控制面的 Linux 环境提供配置。本地契约测试不等同于 Windows 原生运行验收。

项目状态存于 `.digital-employee/workbench/experiments.v1.json`，包含 schema、enabled 和 revision。文件缺失默认关闭，损坏或不安全的路径会停用建议。通过设置页恢复为关闭后可以重新开启；写入失败会显示错误，不应将未保存状态当作持久化成功。手工修改文件在下次设置读取或建议请求时校验，不提供文件监视器。

## 控制面 API

三个端点均要求既有 boot-token 鉴权：

- `GET /experiments?workspacePath=…`：只读当前项目状态、服务是否配置及披露信息，不返回密钥。
- `PATCH /experiments`：`{workspacePath, workspaceSession, revision, enabled}`，按项目串行写入。
- `POST /reports/advice`：`{workspacePath, workspaceSession, revision}`，服务端读取真实报告，调用方不能上传任意判断内容。

`workspaceSession` 是每次打开项目生成的临时标识；A→B→A 后旧请求不可复用。版本或项目不匹配返回 409，客户端重新读取状态再由用户重试。服务不可用返回受限原因枚举，原始服务响应及凭据不会透传。关闭或切换时取消请求并清缓存，服务成功结果只保存在内存中。

## 验证边界

自动化测试应覆盖默认关闭零调用、隔离与重启、明确开启、受限字段、单批上限、缓存去重、超时及非法答案、关闭/切换竞态，以及真实桌面设置与报告交互。测试 provider fixture 能验证契约和降级行为，不能证明线上 Jev 账号可用或建议质量。人工 review 和 Windows 原生运行验收分别记录。
