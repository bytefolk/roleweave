# CXO 案例发现的通用能力缺口

状态：独立功能待办。2026-10-13 由 CXO 入门案例整理，2026-10-14 补充执行团队的验证与修复结论。这些案例只添加参考岗位、示例工作区、操作方法、生成校验工具和验证；本文件不承诺下列能力已实现，不新增 CXO 专用运行逻辑。

## 现有能力与案例用法

现有工作区打开、岗位设置、招聘、组织变更、岗位预算、个人会话、群组成员选择、并行及接力执行、可信终态记录和回读可用于本案例。岗位汇报关系不决定群组执行顺序；接力顺序由请求中的显式成员顺序给出。

`packages/shared/src/workflows.ts` 已有工作方法、任务和交接的类型与校验。该文件明确不提供持久化、Agent 执行或 HTTP 接口，不能把已有类型当作完整工作流引擎。

## 单独评估的功能

| 缺口 | 当前案例如何操作 | 通用功能方向 | 验收重点 |
| --- | --- | --- | --- |
| 案例发现与复制 | 用户复制场景目录，再打开副本 | 统一示例目录与导入/实例化入口 | 能载入 CXO、开源维护等不同案例；不覆盖现有工作区，不导入运行记录或凭据 |
| 参考岗位转为招聘草稿 | 用户阅读 catalog 并填写招聘配置 | 从任意岗位定义预填现有招聘草稿 | 显示来源和可编辑字段；不因职称授予权限，不绕过预算与包校验 |
| 结构化组队建议 | CXO 在会话中给建议，用户选择成员 | 通用的组队草稿、验证与确认 | 稳定岗位 ID、成员、交付物与缺口明确；建议不自动招聘、调岗或运行 |
| 能力与可用性匹配 | 用户查看岗位能力、连接和当前任务 | 通用岗位匹配与启动检查 | 检查实际能力、权限、预算、连接和执行冲突；不是按 CEO/CTO 名字匹配 |
| 团队对象与生命周期 | 使用群组；teams.json 明确 sponsor、lead、成员和目的，用户手工映射到群组 | 评估团队是否需独立于群组，或为群组补通用元数据 | sponsor 不自动加入执行组；目标、负责人、成员引用、状态明确；移出团队不裁撤岗位，不改变汇报关系 |
| 可引用交付物与交接 | 用户保存结果，把关键约束放进下一次输入 | 基于既有 Artifact/Handoff 方向补持久化与授权引用 | 验证来源、版本、访问范围和摘录限制；不复制整个前驱目录或凭据 |
| 任务级验收、汇总与继续 | 用户检查时间线和模板中的 PASS/FAIL/NOT_VERIFIED，显式发起后续工作 | 通用任务状态、人工验收与续接 | 回合 completed 不等于业务 PASS；缺证据不当作通过；重启后不自动重复外部动作；明确已接受的结果 |
| 跨团队资源协调 | 单岗位预算和同工作区单活动执行限制 | 评估统一预算预约与跨群组冲突提示 | 不重复计算或虚构共享预算；超限时有真实停止和恢复路径 |
| 跨版本组织名称兼容 | 场景使用 ASCII business ID，中文名称放在说明中 | 核对工作台创建路径与框架版本的名称契约 | 本次使用的框架 `8a8a2a3` 对 business 采用路径安全标识规则；RoleWeave 创建表单允许中文名称。独立确认展示名与稳定 ID 的映射，不在案例里放宽底层契约 |
| 跨群组依赖与阶段门禁 | 案例列出产品→研发/市场→交付的依赖，用户审阅并传递关键产物 | 通用阶段依赖、授权产物交接及继续条件 | 依赖有可信证据才进入后续阶段；不把 JSON 资料误当已经实现的 DAG 引擎，不隐式共享目录或整段上下文 |
| 验证与有限修复循环 | 用户解读 QA 结论，只 @ 涉及的实现岗位；最多三次验证尝试，之后升级 | 通用验收结论、修复范围、尝试账本与升级控制 | 独立验证者与实现者分开；业务 FAIL 不变成伪造的执行失败；NOT_VERIFIED 不算 PASS；恢复时不重复派发，次数和权限不能靠提示词绕过 |

优先顺序建议：示例复制和招聘草稿 → 组队建议确认及启动检查 → 有证据的交付物与任务继续。每项按独立需求或 PR 推进，而不是随案例资产增加一整套公司管理功能。

## 仓库边界

- RoleWeave：案例资产、用户交互、本地组织/群组/任务控制面。
- digital-employee：岗位包契约、组织和权限预算校验、Host 执行。只有确实缺少底层协议或执行支持时才提交对应改动。
- design-system：新增且可复用的视觉组件。
- digital-employee-platform：案例商品化后再接商品、报价、计量、结算。

这些缺口可以由任何组织案例触发，没有要求底层识别固定的 CXO 名单。

## 执行团队案例已验证的边界

十九岗位工作区和四条 runbook 可使用现有群组进行显式并行及接力。确定性 HTTP 测试覆盖阶段收件人、人工选择的跨团队材料、FAIL 后不自动派发、人工修复复验和三次失败后的人工升级；平台运行时没有因此新增阶段引擎、验收状态或循环调度。

参考方法来自 Agency Agents、BMAD、MetaGPT、CrewAI、gstack、oh-my-claudecode 和 ChatDev，来源另列在 examples/cxo-company/methods.json。方法、岗位和案例资料仍位于 RoleWeave；真实编排协议或 Host 能力缺口按仓库边界单独提需求。
